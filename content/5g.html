interfaces

in general it defines the connection between two things and defines how they can interact with each other; each interface has its own rules and protocols that it operates on.

one way to think about it is that the further apart these two things are in the network, the more this interface has to consists of. for example, if the two things are two endpoints in the network, then the mechanism of the interface has to involve lots of the network protocol stack (which is close to this case here); if the two things are two processes on the same host, the interface might just be the interprocess communication protocols. anyways, think of what boundaries are being crossed.

so of course it's a super abstract path, since ue cannot directly connect to the core amf. instead, it must go through the radio network which must relay the connection to the core.

  • NG interface (next generation interface) is just n2, only n2 has a special name; supports exchanging signals between the 5GC and the NG-RAN; on the application layer of this connection runs the NGAP protocol.

core services

amf (service)

central component of the core services, interacts with many other services.

  • registration management
    • handles initial registration, authorize, and create and update UE context and status (updates happen periodically)
  • connection management
    • establish and release control plane connection with UE (e.g., "UE context release")
  • reachability management
    • maintains knowledge of UE location in the network
    • updates mobility tracking area
    • handle handovers between base stations
  • access authentication
    • authenticates UE during initial registration and periodic updates
    • verifies UE identity and SIM credentials
    • NAS is the protocol through which these authentication messages are sent
  • (pdu session establishment) packet data unit; establishing a logical connection between UE and the core network; smf is responsible for this part, which in turn also interacts with other services;
    • UE initiates a pdu session by sending a request, which clarify the type of service and type of data that will be sent across;

cell selection

usually, ue is surrounded by many cells and can detect their signals; however, it can only camp on cell and use that one service; it must pick the best available cell that matches its registered or selected network and policies.

  • a cell can be suitable (one it can sure connect to), and acceptable (not suitable but can be used as an emergency cell), and maybe be none of them; and out of all the suitable cell, ue will look at the signal strength it seems like.
  • interestingly, if ue camps successfully and normal on a cell, it enters a idle state (just pointing out that it might be a confusing word)
  • ue will also periodically compare the priority and signal quality of the current cell with neighboring cells, and if it meets another cell with higher priority or better signal quality, it might initiate a cell reselection process; the access network might also force a reselection. ref: full process here

sa initial attachment

stands for Stand Alone initial attachment; process in a nutshell (first layer bullet points):

  • as soon as UE powers on, this process starts
  • ue searches for near-by cells and gets the cell's synchronization signals (pps and sss) to synchronize with the gnb timing (two phases: downlink and uplink synchronization)
    • primary synchronization signal (pps) and secondary synchronization signal (sss)
    • downlink sync: phone scans around and learns cell's timing and frequency
    • uplink sync: cell sends back phone a timing correction and the phone applies onto itself
      • uplink sync is achieved by the RACH process (random access channel), where UE sends a randomly chosen preamble to the gNB, and then gNB responds with a timing adjustment
  • RRC connection establishment
    • stands for radio resource control; it's a protocol; TODO.
    • ref
  • UE sends registration request to AMF to register to the network
  • (mutual) UE and network performs authentication process
  • (mutual) UE and network performs security process (two phases: NAS and RRC security)
  • Network Acceptance: The AMF sends a Registration Accept message to the UE, confirming successful registration and providing configuration information such as the UE's 5G-GUTI (Globally Unique Temporary Identifier).
  • RRC Reconfiguration: Network reconfigures RRC for the registered UE based on various UE capability.
  • PDU Session Establishment: The process of establishing data pipe. UE initiate the process and network respond to the request and setting up the data pipe.

ran architecture

CU-CP

The CU-CP, or Central Unit - Control Plane, is responsible for the handling of control plane messaging, specifically, the control plane part of the PDCP protocol. In the CU-CP, there are five main components and four main interfaces. The CU-CP communicates directly with the 5G Core (via the N2 interface), the CU-UP (via the E1 interface), the DU-high (via the F1-c interface) and can also be connected to the near-RT RIC (via the E2 interface). This implementation takes a UE-centric approach. - near-RT RIC -- near-realtime ran intelligence controller

Components:

  • CU-UP Processor: Custom component for handling each CU-UP connected to the CU-CP. Multiple CU-UPs can be connected to one CU-CP, as a result the E1AP is created inside the CU-UP processor for each connected CU-UP.
  • DU Processor: Custom component for handling DUs for connected to the CU-CP. Each connected DU has its own DU processor with bundled F1AP, PDCP, and RRC procedures. Each UE connected to the DU also has its own RRC UE containing the PDCP processes.
    • DU -- distributed unit
    • PDCP -- packet data convergence protocol
      • PDCP does seems very simple. Just "adding the PDCP header to the incoming data and forward to RLC in downlink", or "removing the PDCP header from the incoming packet and forward it to IP layer in case of uplink"
    • RRC -- radio resource control
  • UE Manager: Custom component for managing connected UEs in the CU-CP. Responsible for adding and removing UEs and providing relevant UE information to other processes. Communicates information to/from the CU-UP, DU and Core.
  • Measurement Manager: Custom component for managing cell measurement within the gNB.
  • Mobility Manager: Custom component for managing UE mobility in the CU-CP.

CU-UP

The CU-UP, or Central Unit - User Plane, is responsible for the handling of user plane messaging. Specifically the user plane aspect of the PDCP and SDAP protocols. In the implementation of the CU-UP, there are four main components and four main interfaces. The CU-UP communicates directly with the UPF in the 5G Core (via the N3 interface), the CU-UP (via the E1 interface), the DU-high (via the F1-u interface), and can also be connected to the near-RT RIC (via the E2 interface).

Components:

  • UE Manager: Custom component for managing connected UEs in the CU-UP. Responsible for adding and removing UEs and providing relevant UE information to other processes. Communicates information to/from the CU-CP, DU and Core.
  • GTP-U: The GPRS Tunneling Protocol - User Plane (GTP-U) is responsible for transporting User Plane traffic to and from the UPF of the 5G Core via the N3 interface.
  • SDAP: The Service Data Adaptation Protocol (SDAP) is responsible for adaption and mapping of Quality of Service (QoS) requirements on User Plan traffic.
  • PDCP: The Packet Data Convergence Protocol (PDCP) is responsible for handling the User Plane data before/ after it enters the DU-high.

DU-High

The DU-high, or Distributed Unit - High, is responsible for the handling of both uplink and downlink traffic. Specifically the MAC and RLC processing of these signals. The DU-high, has three main components and three main interfaces. The DU-high communicates directly with the CU-CP and CU-UP via the F1-c and F1-u interfaces, the DU-low via the FAPI interface, and can also be connected to the near-RT RIC via the E2 interface.

Components:

  • DU Manager: The DU Manager is responsible for managing the DU, specifically the connected UEs and RAN Resources.
  • RLC: The Radio Link Control (RLC) layer sits between the MAC in the DU-high and the F1AP/PDCP in the CU, and provides the transport services for SRBs and PRBs between these layers. It operates in three modes: transparent, unacknowledged and acknowledged.
  • MAC: The Medium Access Control (MAC) is responsible for the encoding and decoding of MAC PDUs, scheduling uplink and downlink grants and other control services.

MAC

The main responsibilities of the MAC are:

  • Encoding and decoding of MAC PDUs that are sent/received to the PHY via the FAPI interface
  • Contains the gNB scheduler, which allocates DL/UL grants for System Information, Paging, UE data (RLC PDUs + MAC CEs) and Random Access handling.
  • Demultiplexing and forwarding of decoded MAC Rx SDUs to their respective logical channel.
  • Handle received MAC CEs
  • PRACH handling and RNTI allocation

DU-low

The DU-low, or Distributed Unit - Low, is responsible for the handling of both uplink and downlink traffic. Specifically, it handles the Upper PHY processing related to these signals. The DU-low, contains only the Upper PHY and has two main interfaces. The DU-low communicates directly with the DU-high via the FAPI interface, and with the RU via the Open FrontHaul (OFH) interface. The lower PHY processing is carried out in the RU. This architecture is specific to ORAN Split 7.2.

Components:

  • Upper PHY: The Upper PHY handles the processing of UL and DL signals coming from and to the RU.

random topics

turning info into waves

  • (modulating signal) the wave that carries actual information; different types of information (e.g., video, audio, digital) each have a natural frequency range that it falls into.
  • (carrier signal) we want to modulate the actual signal onto a carrier signal so that the signal is on a special frequency (one that the receiver is configured to listen on), as opposed to having it in its natural frequency; since in the latter case, all signals collide. ref to a good stack exchange answer
  • (signal modulation) manipulate one or more properties of periodic waveforms to carry information. the vanilla signal is called the carrier signal.
    • amplitude modulation (AM) - e.g., am radio, TV signal
    • frequency modulation (FM) - e.g., most other things?
    • pulse modulation (rare and antiquated) - toggling the sine wave on and off
  • (modem) stands for modulator-demodulator; has a transmitter and a receiver; modulates analog signal to digital data and the other way around; allows all wireless communication.
  • (hertz) unit of frequency, one hertz = one event per second.

two frequency ranges

In NR, there are two large frequency range specified in 3GPP. One is what we usually call "Sub 6 Ghz" (also FR1) and the other is what we usually call "millimeter wave" (mmWaves, also FR2). Depending on the ranges, the maximum bandwidth and subcarrier spacing varies.

corresponding frequency range band
FR1 450-6000 MHz n1-n102
FR2 24250-52600 MHz n257-n263

In Sub 6 Ghz, the maximum bandwidth is 100 Mhz and in millimeter wave range the maximum bandwidth is 400 Mhz. Some subcarrier spacing (15, 30 Khz) can be used only in Sub 6 Ghz and some subcarrier spacing (120 Khz) can be used in millimeter wave range only, and some subcarrier spacing (60 Khz) can be used both in sub 6 Ghz and millimeter wave range.
